# Lens 4 — Negative space as the constraint
Generated by: Claude Sonnet

## Candidate L4-1 — Lacuna (connected-empty invariant)

- Lens: 4 (negative space)
- Generated by: Claude Sonnet
- Rule changes:
  - All empty cells on the board must remain 4-connected at all times (after every placement, the set of empty cells forms exactly one connected component).
  - A placement that would fragment the empty region into two or more disconnected pockets is illegal.
  - Pre-fill: generator seeds K filled cells that already satisfy the invariant; tray contains exactly enough pieces to reach the win state.
  - Line-clear rule unchanged.
- Win condition: tray is empty AND the board matches a target pattern (same as puzzle mode).
- Lose condition: no legal placement exists for any tray piece on the current board (all candidate positions fragment empty space or physically overlap filled cells).
- New question per placement: "Does placing here cut the remaining empty region into isolated pockets?" — every placement forces a flood-fill decision not present in base game. The question changes each turn because the empty region's topology changes with each piece placed.
- Dual-purpose mechanic: placing a piece simultaneously fills cells toward the target AND risks severing the empty region. The same action that advances the solution potentially kills future placements.
- Antagonist: the pre-filled seed cells; their shape determines which placements are legal, and the player must route around them without disconnecting empty space.
- Negative-space constraint (THE ENGINE): the empty cells must form one 4-connected component after every placement. The player actively routes pieces so the empty region stays a single blob, not many holes. Planning the boundary between filled and empty is the core verb.
- Order coupling: piece A placed in position X may leave an empty region topology that makes piece B's only legal positions disappear; reverse order preserves B's options. The same set of pieces in different orders can produce legal vs. illegal boards.
- Breathe check: this rule is NOT implied by the target-match or tray-empty conditions. A board can match its target with disconnected empty pockets (e.g. place pieces that isolate a corner). The invariant adds a new sub-condition.
- Generator notes: forward simulation; generator places pieces in reverse, checking connectivity each time, so every output instance is solvable by construction.

## Candidate L4-2 — Quarantine (empty-region size targets)

- Lens: 4 (negative space)
- Generated by: Claude Sonnet
- Rule changes:
  - At game start the board is partitioned into K named empty regions by pre-filled "wall" cells (colored distinctly as antagonist).
  - Each region carries a numeric target T_i displayed in one cell of that region.
  - Win requires every connected empty region to have size exactly T_i at round end.
  - Pieces may span across wall boundaries only if both sides remain non-zero-sized; a piece may NOT be placed such that it reduces any region to 0 cells (eliminates a region) unless that region's target is 0.
  - Line-clear rule unchanged; clearing a wall row would violate the partition — wall cells are indestructible (do not clear).
- Win condition: tray empty AND for every connected empty region, |region| == T_i assigned to that region.
- Lose condition: no tray piece can be placed without violating a region-size constraint OR physically impossible to place any piece.
- New question per placement: "Which region does this cell come from, and will the remaining cells in that region still hit its target?" Every placement is a subtraction from a per-region budget; the question is distinct from base game and distinct each turn as budgets deplete.
- Dual-purpose mechanic: a piece placed at a region boundary simultaneously uses cells from two budgets — could balance or destroy both. The piece is wanted for one region, feared for the other.
- Antagonist: wall cells (indestructible pre-fill) that lock the partition structure; player cannot dissolve walls to simplify the problem.
- Negative-space constraint (THE ENGINE): each empty region has an exact-size target. The player manages the boundary between filled and empty within each region independently: overfill one region by one cell and it is permanently wrong. Active bookkeeping of per-region emptiness is mandatory.
- Order coupling: filling cells in region A first may make a piece that bridges A and B unplaceable (A budget exhausted); filling B first may enable the bridge piece, unlocking A. Ordering across regions determines feasibility.
- Breathe check: region-size equality is NOT implied by tray-empty alone. With an arbitrary tray, multiple ways to empty the tray leave different region sizes. An explicit per-region check is needed.
- Generator notes: forward simulation assigns T_i = initial region sizes minus the cells each piece will fill per region; generator validates a solution path exists.

## Candidate L4-3 — Airlock (empty corridor must span board)

- Lens: 4 (negative space)
- Generated by: Claude Sonnet
- Rule changes:
  - At all times a contiguous empty path must exist from the left edge (column 0) to the right edge (column BOARD_SIZE-1). "Empty path" = 4-connected sequence of empty cells touching col 0 on one end and col BOARD_SIZE-1 on the other.
  - Placement that severs this horizontal corridor is illegal.
  - Pre-fill: generator seeds filled cells that already leave a viable corridor. The corridor may be narrow (1 cell wide) or winding.
  - Line-clear rule unchanged; clearing a row can open new corridor options.
  - Tray and piece types unchanged.
- Win condition: tray empty AND board matches a target pattern; the corridor constraint only restricts placement legality, not the win check itself.
- Lose condition: tray is non-empty AND no piece can be placed without severing the corridor (or without overlapping filled cells).
- New question per placement: "Does this cell close off the last remaining path from left to right?" The player maintains a mental model of the corridor's current minimum-width critical cells — a connectivity check across the board, absent from base game. Changes every turn as the corridor shifts.
- Dual-purpose mechanic: a piece placed in the lower half might fill cells that are both part of the target pattern AND narrow the corridor, making it simultaneously necessary and dangerous.
- Antagonist: pre-filled cells whose placement forces the corridor through specific narrow passes; the player must thread pieces around the bottlenecks.
- Negative-space constraint (THE ENGINE): an empty left-to-right path is a perpetual boardwide constraint. The player actively engineers which cells stay empty to keep the corridor alive. Deciding "this row's middle cell must stay empty to keep the path open" is the primary planning verb.
- Order coupling: placing a piece that fills a corridor-adjacent cell first may block a large piece later; later placements have fewer safe positions around the corridor's critical cells.
- Breathe check: the corridor condition is NOT implied by the target pattern. A target pattern can be satisfied while blocking all left-right paths. The corridor is a separate structural condition.
- Generator notes: BFS-based corridor check per candidate placement; generator forward-simulates a solution path verifying corridor survives at each step.

## Candidate L4-4 — Fault (no two diagonally adjacent empty cells in same zone)

- Lens: 4 (negative space)
- Generated by: Claude Sonnet
- Rule changes:
  - The board is divided into two zones: top-left triangle (row + col < BOARD_SIZE) and bottom-right triangle (row + col >= BOARD_SIZE).
  - Win condition requires that in each zone, no two empty cells are diagonally adjacent (i.e. for any empty cell (r,c) in a zone, the cells (r+1,c+1), (r-1,c-1), etc. that are also in the same zone must be filled).
  - This constraint is a win-state check only, not a placement legality check — the player can place freely, but the final board must satisfy it.
  - Pre-fill: generator seeds cells and a tray such that a solution exists.
  - Line-clear rule unchanged.
- Win condition: tray empty AND board matches target pattern AND for each zone, no two empty cells in that zone are diagonally adjacent.
- Lose condition: tray non-empty AND no legal placements remain (standard block-out).
- New question per placement: "Does placing here leave a diagonal empty pair in this zone?" The player tracks diagonal empty neighbors in each zone, a constraint invisible in base game. The dual zone structure means one piece can create or resolve diagonal violations in both zones simultaneously.
- Dual-purpose mechanic: a piece fills cells in both zones if it straddles the diagonal boundary; it is simultaneously wanted to resolve a violation in one zone and feared for creating one in the other.
- Antagonist: pre-filled cells that force diagonal empty pairs to form unless handled carefully.
- Negative-space constraint (THE ENGINE): empty cells cannot neighbor diagonally within a zone. The player actively ensures that each empty cell's diagonal neighbors are filled — "guarding" the empty cells by surrounding them appropriately. Empty topology is the puzzle.
- Order coupling: filling one diagonal cell early leaves its partner unguarded; filling the partner next resolves it. Reverse order (partner first, original second) may leave fewer pieces to handle another diagonal pair.
- Breathe check: the diagonal-empty rule is NOT implied by the target pattern. A target pattern can include adjacent empty diagonals (the generator won't place target=true cells there, but empty cells can still be diagonal if the target doesn't specify them). Explicit check required.
- AUTO-REJECT flag: PARTIAL. The diagonal rule is a somewhat arbitrary geometric constraint; the "structural aha" — why diagonals, not orthogonals? — is not motivated by the game's primitives. The zone distinction feels flavor-driven rather than mechanic-driven. Keeping for record.

## Candidate L4-5 — Vault (enclose an empty region to score)

- Lens: 4 (negative space)
- Generated by: Claude Sonnet
- Rule changes:
  - A new scoring primitive: an "empty vault" is a maximal 4-connected set of empty cells that is completely enclosed by filled cells AND/OR board edges (no empty cell in the vault can reach the board boundary via 4-connected empty path).
  - Generator pre-defines K target vault sizes [V_1, V_2, … V_K]. Win requires exactly K vaults of those sizes to exist at the end.
  - Line-clear rule unchanged; clearing a row may open a vault or break one.
  - Tray and pieces unchanged.
- Win condition: tray empty AND there exist exactly K enclosed empty regions with sizes exactly matching [V_1 … V_K] (multiset equality).
- Lose condition: tray non-empty AND no legal placements remain.
- New question per placement: "Does placing here close off an empty region (creating a vault), and is that vault the right size?" Vault creation is irreversible — once enclosed, the size is fixed unless a clear happens. Every placement near a partial vault boundary is a commit decision with no undo.
- Dual-purpose mechanic: a line clear is simultaneously welcome (clears space for future pieces) and feared (may destroy a vault you were building or accidentally complete one at the wrong size).
- Antagonist: pre-filled cells that partially surround regions of specific sizes; the player must complete the enclosure at exactly the right moment.
- Negative-space constraint (THE ENGINE): the player actively constructs rings of filled cells around calibrated empty pockets. Every cell placed on a would-be vault wall changes the enclosed size. Managing which cells remain empty — and in what configuration — is the central planning act.
- Order coupling: placing a wall cell prematurely may lock in a vault at the wrong size; placing a non-wall piece first may allow a line clear that disrupts the enclosure. Order determines whether the vault seals at V_i or V_i-1.
- Breathe check: vault-existence at target size is NOT implied by tray-empty or standard win conditions. A board can empty the tray without enclosing any empty region. Explicit vault detection required at win check.
- Generator notes: generator places the vault walls and seeds the tray by backward simulation; verifies that clears do not inadvertently destroy a required vault on the solution path.

## Candidate L4-6 — Moat (empty ring around a filled interior)

- Lens: 4 (negative space)
- Generated by: Claude Sonnet
- Rule changes:
  - A "moat cell" is any empty cell that is orthogonally adjacent to at least one filled cell.
  - Win condition adds: every filled cell must have at least one orthogonal neighbor that is empty (i.e. no filled cell may be completely surrounded by other filled cells — every filled cell must touch the moat).
  - Equivalently: no 2×2 fully filled square may exist at win-state (a 2×2 fully filled block has interior cells touching only filled cells).
  - Pre-fill and tray unchanged; the rule applies only to the win-state, not during placement.
- Win condition: tray empty AND target pattern matched AND no filled cell is completely surrounded by four filled orthogonal neighbors.
- Lose condition: tray non-empty AND no legal placements remain.
- New question per placement: "Does placing here create an interior filled cell with no empty neighbor, and can I fix that with remaining pieces?" The player tracks filled-cell adjacency toward the moat boundary — invisible in the base game. Every placement into a dense region risks creating an interior cell.
- Dual-purpose mechanic: a piece placed in a gap simultaneously fills toward the target AND risks completing a 2×2 interior block, which kills the moat condition. The same piece is needed for target coverage but feared for density.
- Antagonist: the generator pre-fills cells at high density near the center; the player must carve "breathing holes" without violating the target pattern.
- Negative-space constraint (THE ENGINE): the player must preserve a moat — a continuous zone of empty cells adjacent to every filled cell. Empty cells adjacent to filled cells are functional: they are the moat. The boundary between filled and empty must be managed so it stays a proper interface rather than having filled cells swallowed by fill.
- Order coupling: placing two pieces that together form a 2×2 in different orders may be legal (neither alone creates a surrounded cell) or illegal depending on which piece's neighborhood is examined first; since the check is at win-state, order determines which board configuration you can achieve, not whether moves are legal.
- Breathe check: the no-interior-filled-cell rule is NOT implied by the target pattern. A target pattern can include filled cells surrounded on all four sides by other filled cells. This adds a new geometric constraint. HOWEVER — this is close to Breathe disease if the target pattern is always generated to avoid 2×2 filled clusters. Generator must be tested to confirm the constraint is non-trivially non-implied.
- AUTO-REJECT flag: PARTIAL. The constraint is only checked at win-state, not per-placement, which weakens the "order matters" ingredient. The moat condition could trivially be satisfied by any sparse fill. Further: if the target pattern itself is generated with the constraint, the generator effectively encodes the constraint into the target, approaching Breathe disease. Flagged for review.

## Candidate L4-7 — Rift (row emptiness threshold for clears)

- Lens: 4 (negative space)
- Generated by: Claude Sonnet
- Rule changes:
  - Line-clear trigger is INVERTED per row: a row clears when it contains at most E_clear empty cells (default E_clear = 2; difficulty controls this number). Rows that are full do NOT clear.
  - Columns are cleared when they contain at most E_clear empty cells as well.
  - A "rift" is a row/column with exactly 0 filled cells (completely empty). Rifts score +1 toward the win total.
  - Win condition: accumulate R_target rift clears before the board fills up (no room for any tray piece).
  - Lose condition: board fills up before R_target rift clears are collected.
  - Tray and pieces unchanged.
- Win condition: rift_clears >= R_target before lose condition.
- Lose condition: no legal placement exists for any tray piece AND rift_clears < R_target.
- New question per placement: "Does placing here keep this row/column near the low-fill threshold needed for a rift clear, or does it push it toward the high-fill dead zone?" Pieces are simultaneously needed (fill must go somewhere) and feared (overfilling a row kills its rift potential). The question is opposite to classic mode.
- Dual-purpose mechanic: the piece is the rift engine and the rift killer — placing in row R contributes to a rift clear IF that row has few enough empty cells, but it also permanently reduces the row's empty count by the piece's footprint in that row. The player wants to place pieces that push rows toward the rift threshold without going past it.
- Antagonist: the tray itself; each new piece must go somewhere and every placement risks pushing a row out of rift range. The tray is the antagonist by default.
- Negative-space constraint (THE ENGINE): keeping rows/columns near-empty (but not completely empty) is the planning engine. The player actively manages how many cells remain empty in each row, routing pieces to rows that can absorb fill without killing rift potential. Deciding which rows to "protect" as empty corridors is the negative-space management act.
- Order coupling: filling row A first may consume the rift candidate with too many cells, leaving only dense rows that can't rift; saving row A for later (after row B rifts and clears) allows row A to absorb later pieces safely.
- Breathe check: the rift-clear count condition is NOT implied by the classic score or board-fill. Rift clears are a new event type defined specifically by row emptiness, not by fullness. Explicit rift counter required.
- Generator notes: forward simulation. Generator fills pieces until R_target rift clears have been achieved; verifies by replay that no earlier move kills all rift-eligible rows before target is met.

## Candidate L4-8 — Seam (empty cell must separate every pair of same-color filled cells)

- Lens: 4 (negative space)
- Generated by: Claude Sonnet
- Rule changes:
  - At win-state, every pair of orthogonally adjacent filled cells must have different colors (i.e. no two same-color cells may touch orthogonally). This is a win-state check, not a placement legality check.
  - Generator assigns colors to tray pieces such that the constraint is satisfiable; it also pre-fills some cells (antagonist) with colors that force specific empty cells to exist as seams between same-color regions.
  - The player may NOT re-color pieces; colors are fixed at tray generation.
  - Line-clear rule unchanged; clearing a row may remove seam-violations or create new ones.
- Win condition: tray empty AND board matches target pattern AND no two orthogonally adjacent filled cells share a color.
- Lose condition: tray non-empty AND no legal placements remain.
- New question per placement: "Does placing this color here create an orthogonal adjacency with the same-color filled cell at (r,c), and can the remaining empty cells between them serve as seams?" The player tracks color adjacency at every boundary, which is a new decision absent from the base game. Importantly, the EMPTY cells are the seams — the player must leave specific cells empty to prevent same-color contact.
- Dual-purpose mechanic: a piece of color C placed near another C cell must be separated by an empty seam cell. The empty seam cell is simultaneously wanted (prevents color violation) and feared (reduces space available for remaining pieces). The same empty cell serves two purposes.
- Antagonist: pre-filled cells whose colors force specific empty cells to be seams, constraining the remaining legal placements.
- Negative-space constraint (THE ENGINE): the player manages the empty seam boundary between same-color filled regions. For each same-color pair of cells that would be adjacent, at least one intervening empty cell must exist. The player actively routes which cells to leave empty to prevent color adjacency violations.
- Order coupling: placing piece A (color red) in position (r,c) locks in a same-color adjacency risk; the next red piece must now be placed either far away or with an empty seam cell explicitly reserved between them. Piece order determines which cells are committed as seams and which remain free.
- Breathe check: the no-same-color-adjacency rule is NOT implied by the target pattern alone. The target pattern only specifies which cells are filled, not the color arrangement. Two adjacent target cells might both end up the same color under some placement sequence. The color-adjacency check is a new condition.
- Note: this mode is closely related to Chroma mode (which uses a 3-color palette and enforces no-different-color adjacency during placement). Seam mode inverts the rule (same-color forbidden, different-color allowed) and applies it at win-state rather than during placement, and explicitly uses empty cells as the buffer mechanism. However, the similarity to Chroma is a duplication risk. Flagging for registry cross-check.
- AUTO-REJECT flag: PARTIAL. The empty-seam mechanism is genuine negative-space management, but the inverted Chroma similarity means the "structural aha" may not be distinct enough. Kept for record.
